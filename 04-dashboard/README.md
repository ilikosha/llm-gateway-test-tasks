# LLM Requests Dashboard

SPA-дашборд по запросам к LLM API: таблица с сортировкой и пагинацией, фильтры (модель, статус, период), сводные карточки и график задержки во времени. Решение технического задания.

Стек: React 18, TypeScript (strict, без `any`), Vite, TanStack Query, Recharts, Vitest, Tailwind CSS 3.4, ESLint.

## Возможности

- Таблица: пагинация (20 строк), сортировка по времени, задержке и стоимости (клик по заголовку, повторный клик меняет направление).
- Фильтры по модели, статусу (200 / 429 / 500) и диапазону дат. Фильтры, сортировка и номер страницы хранятся в query-параметрах URL: перезагрузка и копирование ссылки сохраняют состояние. Пример: `?model=gpt-4o&status=429&from=2025-03-05&sort=latencyMs&dir=asc&page=2`.
- Карточки: число запросов, доля ошибок (статус >= 400), средняя задержка, общая стоимость. Считаются по отфильтрованной выборке.
- График средней задержки (Recharts), агрегация по 3-часовым интервалам, тоже зависит от фильтров.
- Данные загружаются через TanStack Query с имитацией сетевой задержки (800 мс).
- Состояния: skeleton при загрузке; ошибка с кнопкой «Повторить» (refetch); пустое состояние с кнопкой «Сбросить фильтры», когда фильтры ничего не нашли.
- Адаптивная вёрстка от 360 px: фильтры складываются в столбец, карточки 2x2, график подстраивается под ширину, таблица прокручивается по горизонтали внутри своей карточки (страница не скроллится вбок).
- Тёмная тема: по умолчанию следует `prefers-color-scheme`, кнопка в шапке переключает тему и сохраняет выбор в `localStorage` (с обработкой недоступного хранилища). Цвета графика берутся из CSS-переменных темы.

### Демо состояния ошибки

Добавьте к URL `?simulateError=1` (например, `http://localhost:5173/?simulateError=1`): загрузка данных завершится ошибкой, появится экран с кнопкой «Повторить». Пока параметр в URL, повтор снова даст ошибку; уберите параметр и перезагрузите страницу для нормальной работы.

## Запуск

Нужен Node.js >= 22.18.

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # проверка типов (tsc) + production-сборка в dist/
npm run lint       # ESLint (правило no-explicit-any = error)
npm run preview    # локальный просмотр сборки
```

## Данные

620 записей лежат в `public/data/requests.json` и создаются скриптом `scripts/generate-data.ts`:

```bash
npm run generate-data
```

Генерация детерминирована (фиксированный seed и конец периода), поэтому JSON воспроизводим. Что моделируется:

- 5 моделей с разной долей трафика и ценой за 1M токенов (вход/выход), стоимость = токены x цена;
- логнормальное распределение токенов, задержка зависит от модели и числа выходных токенов;
- ~4.5% ответов 429 (быстрые, без генерации) и ~2.5% ответов 500 (медленные, таймауты); ошибочные запросы не тарифицируются;
- период 14 дней, в рабочие часы (UTC) трафика больше.

```
  useTheme.ts                тема (системная / сохранённая)

  lib/
```

## Принятые решения

- **Бизнес-логика вынесена в чистые функции** (`src/lib`), без React и DOM: легко тестировать, компоненты остаются тонкими.
- **URL как источник состояния.** Хук `useViewState` читает `location.search` при старте и пишет изменения через `history.replaceState`, чтобы каждый клик по фильтру не добавлял запись в историю; `popstate` подхватывает ручные переходы. Значения по умолчанию в URL не пишутся, невалидные параметры игнорируются. Роутер для одной страницы не нужен. При смене фильтров или сортировки страница сбрасывается на первую.
- **Фильтрация на клиенте.** Данных мало (620 записей), поэтому грузится весь набор один раз (`staleTime: Infinity`), а фильтры, сортировка и пагинация считаются в памяти.
- **Даты в UTC.** Границы диапазона включительные (`from` с 00:00:00, `to` до 23:59:59.999 UTC), время в таблице показывается в UTC, чтобы результат не зависел от часового пояса пользователя.
- **Доля ошибок** = запросы со статусом 429 и 500 / все запросы. Для пустой выборки все метрики равны 0, а не NaN.
- **Данные из `public/`, а не из импорта.** Запрос идёт через `fetch` с учётом `import.meta.env.BASE_URL`, поэтому работает при любом базовом пути; это же честно демонстрирует работу с сетью.
- **Tailwind 3.4 + токены темы.** Цвета заданы CSS-переменными (`--c-*`) в `:root` и `:root.dark`, Tailwind ссылается на них, поэтому один набор классов работает в обеих темах, а Recharts берёт те же переменные. Класс `dark` ставится на `<html>` инлайн-скриптом в `index.html` до отрисовки (без вспышки).
- **Типизация.** `strict` + `noImplicitAny`, ESLint с `@typescript-eslint/no-explicit-any: error`; `any` в коде нет.
- Recharts вынесен в отдельный чанк, чтобы основной бандл не раздувался.


## Деплой

### GitHub Pages

Проект лежит в монорепозитории в папке `04-dashboard/`, workflow находится в корне монорепозитория: `.github/workflows/deploy-dashboard.yml`.

Базовый путь задаётся переменной окружения `VITE_BASE_PATH` (по умолчанию `/`). Для репозитория `https://github.com/<user>/<repo>` нужен `/<repo>/`.

1. Запушить монорепозиторий (ветка `main`).
2. В настройках репозитория: Settings, Pages, Source = **GitHub Actions**.
3. Workflow срабатывает на push в `main`, затрагивающий `04-dashboard/**`, а также вручную (workflow_dispatch). Шаги выполняются в `04-dashboard`: `npm ci`, lint, тесты, сборка с `VITE_BASE_PATH=/<имя-репозитория>/`, публикация `04-dashboard/dist`.

Локальная проверка сборки с базовым путём:

```bash
VITE_BASE_PATH=/my-repo/ npm run build && npm run preview
```

Приложение использует query-параметры, а не пути, поэтому SPA-фолбэк (404.html) не требуется.

### Vercel

Импортировать репозиторий в Vercel: фреймворк определится как Vite (build `npm run build`, output `dist`). Переменную `VITE_BASE_PATH` задавать не нужно, базовый путь `/`.
